# AI Here 1.6.1 CLI 工作目录检查

用户报告 Codex CLI 没有先进入工作目录。源码与已安装 1.6.0 逐字相同，原本已有 cd，且没有用 Codex 的目录参数替代 cd；实际日志最近两次选中 ai-here 并路由 iTerm。因此没有把“遗漏 cd”作为已经复现的根因。

发现的脆弱路径是 iTerm 先创建默认 profile 会话，再模拟键入命令，冷启动还有延时与当前窗口复用。1.6.1 改为创建窗口/标签页时直接指定 profile command：登录交互 shell 初始化 → 内置 cd 到所选目录 → 启动 Agent。不会向已经运行的会话写入启动命令。Terminal 使用新的 do script 窗口，不复用冷启动 front window。

cd 使用内置命令和安全引用，失败时不启动 Agent；clear 失败不影响启动。Codex 原有命令参数、绝对路径回退与任务提示传递仍保留。Agent 退出后保留普通交互 shell，退出后的目录遵循用户初始化文件；没有承诺忽略用户主动切换目录的设置。

## 证据

- 56 项测试通过（18.295 秒），独立复查的 16 项启动器测试通过。
- 四种模式 claude-cli / claude-continue / codex-cli / codex-resume 在另一个目录执行生成命令，fake Agent 记录 os.getcwd()，均等于目标目录；中文、空格、单引号、反引号和命令替换字符串保持字面值，参数正确。
- 模拟 clear 失败和自定义 cd 函数，Agent 仍从目标目录启动。
- 目标目录在选中之后消失：cd 非零退出，Agent 没有执行。
- 受控 osascript 传输替身捕获实际 iTerm session command；执行该完整命令，模拟 .zshrc 先 cd /，fake Codex 仍记录正确目标目录。交互 shell 使用 EOF 退出，没有向真实应用发送测试任务。
- iTerm 的窗口/标签页 command 参数由本机 iTerm2.sdef 核实；两个终端 AppleScript 传输段实际编译通过。
- 安装 1.6.1 完成，源码/安装启动器一致；zsh 语法、Git diff 空白、App 深度签名和版本检查通过。
