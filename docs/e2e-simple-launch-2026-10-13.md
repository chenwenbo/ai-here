## 实现与检查

五个既有入口（Claude Code CLI、Codex CLI、Claude 桌面、Codex 桌面、WorkBuddy）每行只有“直接开始”“总结并接续”。保留工作目录与更换按钮；移除材料、自由任务输入、指定记录、恢复会话和交接管理操作。

“直接开始”调用原有工具模式；“总结并接续”调用 `task summarize --cwd --tool --source`，固定提示引用随应用安装的本地 `ai-here-handoff` 技能。高级 CLI 保持兼容。技能缺失时在保存快照与发出启动请求之前失败；快照重新启动仍为总结模式。

52 项自动化测试通过（本次 11.541 秒；独立审查 9.173 秒）。技能结构验证、AppleScript 编译、JavaScript/zsh 语法、Git diff 空白检查、安装与 codesign 检查通过。`doctor --json` 返回 1.5.0；安装后技能与源码字节一致。

## 实际原生 UI

Computer Use 检查了五行十个动作按钮及紧凑布局，并在独立测试目录验证 Claude 桌面的两条实际按钮路由：

- 直接开始：launches 没有新增请求，剪贴板字节摘要不变，工作空间没有初始化交接。
- 总结并接续：新增的私有请求中 tool=claude-app、mode=summarize、cwd 正确；提示引用安装目录中的技能，剪贴板与完整提示字节一致。仅启动提示时项目仍未初始化，没有假报总结完成。
- 不存在的目录：明确失败；点击返回后目录输入保留，面板仍可使用。

本轮没有用原生 UI 向真实 CLI 或桌面 Agent 发送总结任务。CLI 路由及提示单参数传递由受控自动化测试和 dry-run 覆盖。

## 技能实际行为验证

独立 QA Agent 按技能在临时测试工作空间执行总结。原材料有 Claude Code 的旧版本 0.1 记录、Codex 的 0.2 记录，以及当前 README 和只读检查脚本。

实际生成并复读新交接，标为 active：

- 明确当前 README 声明 0.2，不把文档声明等同于功能完成。
- 本次执行当前 check.py 通过，只证明 README 字符串断言；两个启动动作的功能状态仍标未核验。
- 列出旧 0.1 陈述与当前文件冲突，将历史测试结果标为未经独立核实。
- Git 尚无提交，明确记录基线缺失，不把空 git diff 当作没有改动。
- 保存新记录、更新索引最近区，保留业务文件、旧交接和索引手工区；完成后停止，没有执行旧待办。

这验证了技能在该测试场景中的实际表现；技能要求核验，不保证未来所有模型都无误。
