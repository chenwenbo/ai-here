# 工作交接：用户场景与操作路径

适用版本：AI Here 1.3.1。本文描述当前可用操作；文末的改进建议尚未实现。

## 先明确几个共同规则

- **一个项目使用同一个交接目录。** 切换工具时选择同一项目根目录，交接保存在该目录的 `.ai-here/` 中。另一个目录或独立 Git worktree 不会自动同步这些文件。
- **任务结束前先写交接，再切换工具。** Agent 会收到写交接的规则；用户应检查是否产生最新记录。关闭软件或双击另一个 Agent 都不会强制保存上一段工作。
- **交接由当前 Agent 或用户写入。** AI Here 提供初始化、保存、查看和复制能力；它不会自动读取完整聊天并生成总结。
- **下一位 Agent 先读，再核验，再接续。** 文件、提交号、实际验证结果是依据；记录中的完成状态只对应那次任务。

基本路径：**定位项目 → 首次启用 → 完成一段工作 → 写入并确认交接 → 打开下一工具 → 读取并核验 → 继续工作 → 再写交接。**

生成文件的位置：

- 项目根目录的 `.ai-here/index.md`：当前状态和最近交接链接；“查看工作交接”打开它。
- `.ai-here/handoffs/<唯一记录ID>.md`：每次保存产生一份具体任务交接。
- `.ai-here/templates/handoff.md`：正文模板。
- 项目根目录的 `AGENTS.md`、`CLAUDE.md`：让工具读取并写入交接的入口规则。

### Finder 入口怎样定位目录

打开项目根目录，取消对其子文件夹的选择，点击 Finder 工具栏的 **AI Here**，核对弹窗顶部路径。

如果 Finder 已选中一个或多个文件夹，AI Here 会使用选中的文件夹。需要选择项目时，也可以在项目上级目录选中项目文件夹再点击工具栏。避免把交接误建在某个子目录。

每个菜单项都支持双击执行；单击后点“确定”也可以。菜单中的启用、查看和复制是独立操作，完成后若要启动 Agent，需要再次点击 AI Here。

## 场景总览

| 场景 | 用户想做什么 | 主路径 | 成功标志 |
| --- | --- | --- | --- |
| 1. 首次使用 | 让项目拥有共享工作记录 | 项目 → AI Here → 启用交接 | 索引和项目指令已创建 |
| 2. Codex 与 Claude Code 切换 | 让另一工具继续开发 | 当前 Agent 写交接 → 确认记录 → 同目录打开下一 Agent | 新 Agent 能说明已完成、待办及核验结果 |
| 3. 转给 WorkBuddy | 用 WorkBuddy 接续当前项目 | 写交接 → AI Here → WorkBuddy → 用户发送任务 | Agent 读取文件、完成接续并写回 |
| 4. 转给普通 ChatGPT，再带回 | 用 ChatGPT 讨论方案，再回本地执行 | 写交接 → 复制摘要 → 粘贴提问 → 保存回复交接 → 本地 Agent 接续 | ChatGPT 结论已成为本地正式记录 |
| 5. 转给有本地权限的 ChatGPT Work | 在 Work 中直接继续文件任务 | 写交接 → 手动打开 Work → 授权同目录 → 读取并接续 | 本地文件与新交接均保存到同一项目 |
| 6. 隔天继续、开新对话或中途暂停 | 找回进度，避免重新说明 | 结束前写状态 → 下次打开同目录 → 读取最新交接 | 新对话知道停在哪里和下一步是什么 |
| 7. 忘记写交接或记录有误 | 补回缺失记录或纠正旧结论 | 原对话补写 / 用户保存正文 → 查看记录 → 下一 Agent 核验 | 新增可追溯的补写或更正记录 |

## 场景 1：首次给项目启用交接

**例子：** 项目此前没有共享工作记录，准备交替使用 Codex 和 WorkBuddy。

**用户路径：**

1. 在 Finder 定位项目根目录，点击 **AI Here**，确认目录正确。
2. 双击 **启用 / 修复工作交接**。
3. 此时生成索引、交接模板与记录目录，并给 `AGENTS.md`、`CLAUDE.md` 添加读写交接要求；原有内容保留。
4. 再次打开 AI Here，看到“工作交接已启用”，以及 **查看工作交接**、**复制交接摘要 · 用于 ChatGPT 等**。
5. 双击需要的 Agent，开始任务。第一次启用时尚无任务成果记录，先完成一段工作再写入。

**何时生成：** 索引和规则在第 2 步生成；具体任务交接在 Agent 保存时生成。

**可选：** 如果希望记录不进入 Git，执行 `ai-here handoff init ~/项目 --instructions --ignore`。工具栏启用不自动给整个 `.ai-here/` 设置 Git 忽略。

## 场景 2：Codex 与 Claude Code 之间切换

**例子：** Codex 已实现功能，交给 Claude Code 检查并补齐问题。

**用户路径：**

1. 在 Codex 当前对话里说明：“准备切换工具，请保存本次交接，包含改动、实际验证结果、未完成工作与下一步。”
2. Agent 写入一份记录并更新索引。
3. 在 Finder 点击 **AI Here → 查看工作交接**，确认最新记录的来源、时间、产物和下一步。发现没有新记录时，先让当前 Agent 补写。
4. 再次打开 AI Here，确认仍是同一项目目录，双击 **Claude Code CLI** 或 **Claude Code App**。
5. 在新对话中下达接续任务，例如：“读取现有交接，核验当前改动，检查功能是否满足要求并处理剩余问题。”
6. Claude Code 根据项目指令读取索引和相关记录，核对当前文件与 Git 状态后继续。
7. Claude Code 完成或暂停前，再保存自己的交接。

**成功标志：** 新 Agent 能正确复述前一位做过什么、哪些验证实际执行过，以及当前需要完成的事情，并生成自己的产物和新记录。

**反向路径：** Claude Code → Codex 同样适用。项目指令提供读取要求，实际遵循情况仍需确认。

## 场景 3：从本地 Agent 转给 WorkBuddy

**例子：** Codex 已整理数据，WorkBuddy 接着制作文档。

**用户路径：**

1. 当前 Agent 保存交接，用户查看最新记录确认已保存。
2. 在同一项目目录点击 **AI Here → WorkBuddy**，双击打开。
3. WorkBuddy 新任务页预填工作目录、交接索引路径、读取要求和结束前写回要求。
4. 用户核对工作目录，在输入框补充本次任务，然后手动发送。
5. WorkBuddy 读取交接和相关文件，核验前一阶段结果，执行任务。
6. 任务结束前写入新的正式交接；回到 AI Here 查看索引确认来源和结果。

**成功标志：** 已创建并执行任务，产物保存到同一目录，索引出现 WorkBuddy 的新记录。仅看到正确预填提示，尚未完成接续。

**当前验证情况：** 启动与预填已实测；本机 WorkBuddy 5.3.12 两次创建会话均 90 秒超时，实际读写闭环尚未通过。失败时保留既有交接，待客户端能创建任务后重试，或通过同目录的其他 Agent 接续。

## 场景 4：普通 ChatGPT 讨论方案，再回到本地 Agent

**例子：** 本地开发做到一半，希望 ChatGPT 评估需求或方案，然后让 Codex 按选定方案继续。

**带出路径：**

1. 当前本地 Agent 保存交接，包含讨论所需背景、当前产物、约束和待决问题。
2. 在同一目录点击 **AI Here → 复制交接摘要 · 用于 ChatGPT 等**。
3. 用户自行打开普通 ChatGPT 对话，粘贴摘要，再输入具体问题。
4. ChatGPT 根据摘要讨论；未实际读取本地文件的状态应标为未核验。

**带回路径：**

5. 讨论结束时要求 ChatGPT 输出交接正文，包含结论、候选方案、理由、验证边界和下一步。明确哪些方案已经被用户选定，哪些仍待决定。
6. 用户将这段正文保存为本地 Markdown 文件，例如 `~/Downloads/chatgpt-handoff.md`。当前没有“导入 ChatGPT 回复”的图形按钮。
7. 用户在终端执行保存命令，或让有本地权限的 Agent 读取该文件并执行同一保存操作：

   ```bash
   ai-here handoff add ~/项目 --title "方案讨论交接" --agent ChatGPT \
     --status active --body-file ~/Downloads/chatgpt-handoff.md
   ```

8. 回到 Finder，在同一项目目录打开 Codex 或 Claude Code，让它读取新交接、核验实际文件，并执行已经确认的下一步。

**成功标志：** ChatGPT 的结果进入 `.ai-here/handoffs/`，下一位本地 Agent 能读取它。只在 ChatGPT 中收到回复，尚未写回本地交接。

**摘要范围：** 默认包含索引和最近 5 条记录正文，总预算为 12,000 字符，超过会提示截断。旧记录或重要文件内容未包含时，需补充相关材料。

## 场景 5：使用有本地目录权限的 ChatGPT Work

**例子：** 希望 Work 直接读取项目文件，接着处理文档。

**用户路径：**

1. 当前 Agent 保存交接并确认最新记录。
2. 用户在 ChatGPT 中手动打开或创建 Work 会话，选择并授权同一个项目目录。AI Here 当前没有 ChatGPT Work 启动选项。
3. 在 Work 中输入：“先读取 `.ai-here/index.md` 和相关交接，核验当前文件，然后继续处理指定任务。”
4. Work 读取、核验并执行任务。
5. 结束前保存交接。若能执行本地命令，则用 `ai-here handoff add`；若只能读取或输出内容，则按场景 4 的带回路径保存正文。
6. 通过 AI Here 查看交接，确认记录和产物已保存到该项目。

**成功标志：** 有实际的本地文件读取证据、保存的产物和正式交接。仅能在对话里看到文件名不代表拥有读写权限。

**当前验证情况：** 该客户端读写路径未完成实测。

## 场景 6：隔天继续、开新对话或工作中途暂停

**例子：** 今天调试到一半，明天想从一个新对话继续。

**结束前路径：**

1. 告诉当前 Agent 保存交接，写清楚已做什么、停在哪里、复现方法和下一步。
2. 尚有工作使用 `active`；需要外部条件才能继续使用 `blocked`；该次任务已完成使用 `completed`。
3. 查看索引确认已保存，再结束对话或关闭软件。中途也可以主动保存一次进度。

**下次进入路径：**

4. Finder 定位同一项目目录，点击 AI Here，打开需要的工具。
5. 在新对话中要求读取交接并继续；Agent 核验文件与状态后执行。
6. 若希望恢复同一工具自身的历史对话，可选择 **Codex CLI · 继续上次会话** 或 **Claude Code CLI · 继续上次会话**；这些入口恢复对应工具的会话，不会把另一产品的聊天导入进来。

**成功标志：** 新对话能找到暂停点、已有验证和下一步，继续执行并追加进度。

**意外退出：** 未保存的那段工作不会自动总结，需要按场景 7 补写。其他工作目录不会自动获得这个项目的记录。

## 场景 7：忘记写交接、旧记录过期或结论有误

**原对话还在：**

1. 回到原对话，要求结合实际文件和执行结果补写交接。
2. 查看最新记录，确认不把猜测记为已验证。
3. 再按场景 2、3、4 或 5 转给下一工具。

**原对话已不可用：**

1. 用户或下一位本地 Agent 检查当前文件、Git 改动和已有产物，整理能够确认的事实；无法恢复的决策理由标为未知。
2. 保存为交接正文文件，再运行 `ai-here handoff add`；也可在终端运行 `ai-here handoff add ~/项目`，按提示输入标题、工具和正文，正文结束按 Ctrl-D。
3. 查看索引确认新记录，再接续工作。

**发现旧结论错误：**

1. 追加一条更正记录，指出对应旧记录、错误内容、新证据和新的下一步。
2. 需要刷新最近记录清单时运行 `ai-here handoff init ~/项目`，保留索引的手工区。
3. 下一 Agent 对照更正和当前文件核验，避免继续依赖旧结论。

**成功标志：** 补写或更正记录可追溯；未核验与未知事项明确标注。

## 补充：多个 Agent 同时工作

当前独立记录可以并发追加，写入机制有锁，但没有任务认领、文件编辑协调或冲突处理界面。

建议用户先划分任务和负责文件 → 每个 Agent 在同一项目阅读索引 → 分别执行自己的任务并追加交接 → 由一个负责汇总的 Agent 核验产物并更新索引手工区。

独立 worktree 使用各自的目录和记录；需要汇总时由用户或 Agent 将相关正文带入目标工作区。多选文件夹后复制可以合并各目录摘要，前提是选中的目录都已启用交接；这不会合并或同步各目录的记录。

## 当前路径中的产品缺口与改进优先级

| 优先级 | 路径缺口 | 建议的未来操作 | 当前替代方式 |
| --- | --- | --- | --- |
| P0 | 切换前不知道当前 Agent 是否保存 | 点击切换时检查交接新鲜度，提示“先保存交接 / 继续打开”，展示检查依据 | 用户让当前 Agent 保存后查看记录 |
| P0 | ChatGPT 结果带回需要保存文件和命令 | 提供“粘贴交接正文 → 选择来源/状态 → 保存”表单 | 保存正文文件后 handoff add |
| P1 | 只有索引，看不出谁在做什么 | 展示最近来源、保存时间、待办与阻塞状态 | 查看索引和相关记录 |
| P1 | 启动成功容易被误认为接续完成 | 客户端支持时显示读取、执行、写回状态及失败原因 | 检查实际产物和新记录 |
| P2 | 多 Agent 同时工作缺少协调 | 增加任务认领、负责文件和汇总流程 | 用户划分工作并人工汇总 |

这些建议尚未实现。交接时间较新也不能证明已包含所有改动，切换检查应作为提示，不能宣称自动保证保存。

命令详情见 [工作交接指南](cross-agent-handoff.md)；实际验证状态见 [端到端验收报告](e2e-handoff-2026-10-13.md)。
